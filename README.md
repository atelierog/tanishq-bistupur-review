## Product snapshot

This project is a focused QR-driven review experience designed around a real retail workflow: making it easier for customers to reach the review journey after a product demonstration or store interaction.

The project is particularly useful as a product case study because it connects **a real operational problem → customer interaction → digital workflow → feedback loop**.

---

## The problem

In a physical retail environment, asking customers for feedback is simple in theory but easy to lose in the flow of a busy showroom.

The digital experience needs to reduce friction between:

**Customer interaction → QR scan → review journey → feedback**

The project focuses on that narrow workflow rather than trying to build a large review-management platform.

---

## Product approach

The implementation is intentionally lightweight: a web-based experience that can be reached from a QR code and used directly from a customer's phone.

The product thinking behind it is:

1. Keep the customer journey short.
2. Make the experience mobile-friendly.
3. Connect the physical retail interaction to a digital feedback action.
4. Keep the experience simple enough to use immediately after a demonstration.
5. Iterate the experience based on practical store usage.

---

## Why this is a meaningful product project

Unlike a purely hypothetical portfolio exercise, this project was created around an actual retail environment where customer interaction happens in person.

That creates a useful product-development loop:

```text
Real store workflow
       ↓
Customer interaction
       ↓
Identify friction
       ↓
Design QR experience
       ↓
Customer uses phone
       ↓
Review / feedback journey
       ↓
Observe usage
       ↓
Iterate
```

The experience also connects to my day-to-day work at Tanishq, where I interact directly with customers and understand how digital touchpoints fit into a physical retail journey.

## Implementation

The current repository contains a single primary web entry point:

The repository is intentionally small because the product problem is narrow. The goal is to solve one workflow well rather than add unnecessary infrastructure.
